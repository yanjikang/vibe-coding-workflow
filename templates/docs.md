# 开发文档（docs.md）

> **用法**：窗口 1 与 AI 对齐需求后，让它依据《开发计划》生成本文档的初稿；它是所有后续窗口的**背景基准**——
> 架构变动时必须同步更新，否则新窗口读到的就是假架构。
> 交接三件套（① Rules → ② progress.md → ③ 本文档相关章节）中的第三件就是它。

## 1. 系统架构总览

- **架构图**：〔让 AI 用 mermaid 画：模块划分 + 数据流向〕
- **运行形态**：〔纯前端 / 前后端分离 / 单体全栈 / 静态站〕
- **部署目标**：〔例：GitHub Pages / Vercel / 自有服务器〕

## 2. 目录结构约定

```
src/
├── api/          # 请求统一封装（禁止组件内直接 fetch）
├── components/   # 通用组件
├── pages/        # 页面级组件
├── stores/       # 状态管理
├── utils/        # 纯函数工具
└── types/        # 类型定义
```

> 以实际项目为准，但**一经确定写入本文档，所有窗口必须遵守**，这是 Rules 中目录禁令的依据。
